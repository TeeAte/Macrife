# Macrife — macOS 原生 AI 视频补帧

把低帧率视频补成高帧率：24fps → 60fps、30fps → 120fps，**任意目标帧率**（不必是 2 的倍数）。

纯原生 Swift 实现，**完全离线运行**，不上传任何数据、不需要账号、不依赖 Python 环境。
推理走 Apple 芯片的 CoreML + 自写 Metal kernel，视频编解码走 VideoToolbox 硬编。

---

## 一、它能做什么

| 能力 | 说明 |
|---|---|
| 任意目标帧率 | 24→60、30→144、25→50 都行，非整数倍也支持 |
| 码率可调 | 默认 20 Mbps，滑杆可调，H.264 / HEVC 可选 |
| 最高 4K | 576p / 1080p / 1440p / 2160p 四档模型，默认按源分辨率自动选 |
| 保分辨率 | 输出尺寸永远等于源尺寸，不会被缩小 |
| 场景切换检测 | 硬切处自动跳过插值并重复前一帧，避免「双重曝光」鬼影 |
| 音频自动保留 | 默认把原音轨搬进输出（AAC 等格式零重编码），也可关掉 |
| 两种用法 | 图形界面（拖进去就行）+ 命令行（可批处理） |

实测参考（M1 Pro）：1024×576 处理分辨率下约 60 ms/帧；数值对齐 PyTorch fp32 参考 49.7 dB。

## 三、下载与安装

### 1. 下载

到本仓库右侧的 **Releases** 页面，下载最新版：

| 文件 | 说明 |
|---|---|
| `Macrife-<版本>.dmg` | **推荐**。挂载后把 Macrife 拖进 Applications |
| `Macrife-<版本>.zip` | 备选。解压后把 `Macrife.app` 拖进 Applications |
| `SHA256SUMS.txt` | 校验值，用于确认下载没被篡改/损坏 |

校验（可选）：

```bash
shasum -a 256 Macrife-1.0.dmg
# 和 SHA256SUMS.txt 里对应的一行比对，一致即可
```

### 2. 安装

- **dmg**：双击打开 → 把 `Macrife` 图标拖到窗口里的 `Applications` 替身上 → 推出磁盘镜像。
- **zip**：双击解压 → 把 `Macrife.app` 拖进 `应用程序` 文件夹。

### 3. 首次打开：可能会看到「无法打开」

本 App **没有经过 Apple 公证**（作者未使用付费开发者账号签名），macOS 的 Gatekeeper 会拦一下。
**这是正常的，不是文件损坏。** 任选一种方式放行：

**方式 A（推荐，一次就好）** —— 在访达里 **右键** 点 `Macrife.app` → 选「打开」→
弹窗里再点「打开」。之后双击就能正常启动了。

**方式 B** —— 终端里清掉隔离标记：

```bash
xattr -cr /Applications/Macrife.app
```

> 如果看到的是「App 已损坏，无法打开」，也是同一个原因，用上面任一方式即可。

## 四、使用方法

### 图形界面

1. 打开 Macrife。
2. 拖一个视频进窗口（也可以拖到 Dock 上的 Macrife 图标，或在访达里右键「打开方式 → Macrife」）。
3. 选目标帧率（默认 60）、码率（默认 20 Mbps）、编码器（默认 H.264）。
4. 需要保留声音就把「保留音频」打开（默认开）。
5. 点「开始」，等进度条走完。

输出文件：与源文件**同一目录**，文件名是 `<原名>_interpolated.mp4`。

### 命令行

```bash
/Applications/Macrife.app/Contents/MacOS/Macrife \
    --run --in ~/Movies/a.mp4 --out ~/Movies/b.mp4 --fps 60 --mbps 20
```

常用参数：`--fps`（目标帧率）、`--mbps`（码率）、`--codec h264|hevc`、
`--tier auto|576p|1080p|1440p|2160p`、`--noaudio`（不要音轨）、`--dryrun`（只预估不跑）。

## 五、关于模型

档位是模型的处理分辨率，**不是输出分辨率**（输出永远是源尺寸）。

- 精简包内置 **576p** 一档；全档位包内置 576p / 1080p / 1440p / 2160p。
- 默认 `auto`：按源分辨率自动选，且默认封顶 576p —— 因为默认模式下画面细节直接来自源帧，
  档位只影响光流精度；实测 576p 的锐度已优于更高档位，且快一个数量级。
- 想强制更高档位（运动极剧烈、需要更准的光流）：GUI 或命令行显式指定 `--tier 1080p` 等，
  但速度会显著变慢。

想用自己导出的模型：放到

```
~/Library/Application Support/Macrife/models/coreml/
```

该目录**存在时会整体覆盖** App 内置模型，请自备需要的所有档位。

## 六、常见问题

**Q：跑得很慢 / 风扇狂转？**
补帧是逐帧神经网络推理，实时倍速约 5~10× 慢于实时（取决于分辨率与档位）属正常。
降档位（`--tier 576p`）、或先用短片段试。

**Q：输出没有声音？**
先确认源文件本身有音轨。极少数编码（如 Opus）会被转成 AAC；如果音轨探测失败，
程序会退化成「只出画面」并在日志里说明，不会让整条任务失败。

**Q：画面局部抽动 / 抖动？**
只在自己导出模型且尺寸不是 64 的倍数时出现。内置档位已规避此问题。

**Q：会不会上传我的视频？**
不会。全部在本机运算，App 不联网、不收集任何数据。
